# Палитры «Пространство» для desktop (spec 029, T051/T053)

Данные темы для tdesktop: цветовые схемы web (`gruvbox`, `nord`, `catppuccin`, `solarized` × светлая/тёмная;
`telegram` — штатные темы tdesktop) в виде файлов палитры tdesktop и JSON с переменными web. Код tdesktop этим
шагом не менялся.

## Файлы

| Файл | Что это |
|---|---|
| `gen_palettes.mjs` | генератор и проверка; таблица соответствия ключей tdesktop ↔ тонов web — в нём |
| `space-tokens.json` | по схеме и режиму: `palette` (13 тонов), `colors` (`--color-*` из `buildMode`), `tokens` (`--pv-*`), `chatColors`, `swatches`. У `telegram` нет `palette`, `colors`, `chatColors` (в web — «без замен») |
| `space-<схема>-<light\|dark>.tdesktop-palette` | палитра: строки `key: #rrggbb;` / `#rrggbbaa;` |
| `space-<схема>-<light\|dark>.tdesktop-theme` | zip: та же палитра (`colors.tdesktop-theme`) + `background.png` 1×1 цвета `bg` — плоский фон чата |

Все файлы создаются генератором — руками не править.

## Перегенерировать и проверить

Из корня репозитория (tsx уже есть в зависимостях web; `npx vite-node` локально не установлен и скачивается из
сети — не нужен):

```sh
web/telegram-tt/node_modules/.bin/tsx desktop/theme/gen_palettes.mjs          # записать файлы
web/telegram-tt/node_modules/.bin/tsx desktop/theme/gen_palettes.mjs --check  # только проверить
```

Предупреждение Node `localStorage is not available` — от `colorScheme.ts` (читает сохранённую схему при импорте),
безвредно; убрать — `NODE_OPTIONS=--no-warnings`.

Генератор **импортирует** `web/telegram-tt/src/util/colorScheme.ts` (`buildSchemeColors`, `buildSchemeTokens`,
`getSchemeChatColors`, `getSchemeSwatches`); цвета не копируются. `PALETTES` там не экспортирован — 13 тонов
восстанавливаются из переменных, в которые каждый попадает один к одному (`--pv-bg` … `--pv-faint`,
`--color-primary`, `--color-links`, `--color-background-own`, `--color-accent-own`). Производные цвета — той же
функцией `mix` (colorjs.io, смешение в sRGB), что в web.

`--check` падает (код 1), если:
- ключ в файле не существует в `lib_ui/ui/colors.palette`, ключ повторён, строка не вида `key: #rrggbb[aa];`;
- какой-то ключ `colors.palette` со своим hex не решён (не сопоставлен и не помечен штатным);
- файл на диске отличается от того, что генератор создал бы сейчас (поменялась схема web или таблица).

После правки `colorScheme.ts` — перегенерировать и закоммитить файлы вместе с правкой.

## Как tdesktop читает палитру (важно для «штатных» ключей)

`window_theme.cpp LoadTheme` → `loadColorScheme` ставит ключи из файла; затем `palette::finalize` (codegen) для
каждого ключа без записи: если у него в `colors.palette` есть исходный ключ (`key: other;` или `#hex | other`) и
тот загружен — берёт его значение, иначе — своё значение из `colors.palette`, то есть **дневное**. Отсюда:

- копии (`key: other;`) мы не пишем — они следуют за сопоставленным исходным ключом (200 копий следуют за
  сопоставленным, 36 — за штатным);
- **светлый режим**: штатные ключи не пишутся (база — дневная палитра). 130 записей;
- **тёмный режим**: если не записать штатный ключ, он станет дневным. Поэтому генератор повторяет расчёт
  загрузчика и дописывает отдельным блоком значения ночной темы tdesktop (`Resources/night.tdesktop-theme`) там,
  где без записи получилось бы другое (имена собеседников, значки файлов, звонки, тени, …). 130 + 50 записей.
  Это сознательное отступление от «штатные не писать»: иначе тёмная схема получила бы дневные звонки и цвета имён.

## Принципы соответствия

- фон вокруг колонок = `bg` (заголовок окна `titleBg`, рейка папок `sideBar*`, фон чата — `background.png`);
- колонки, список чатов, шапки, меню, окна = `panel` (`windowBg`, от него — копиями `dialogsBg`, `menuBg`,
  `boxBg`, `topBarBg`, `msgInBg`, композер); наведение = `hover`, ripple — `hover` + 10 % текста;
- активный чат и кнопки = `accent` с белым текстом (`dialogsBgActive`, `windowBgActive`, `activeButton*`);
  наведение на акцент — темнее на 7 %, ripple — `--color-primary-shade` (−14 %, как в web);
- входящие = `panel`, исходящие = `own`; значки/ссылки/моно/волна в исходящих — `ownAccent`; выделенное
  исходящее — `--color-background-own-selected`; время в исходящих — `--color-message-meta-own`;
- акцентный текст и ссылки = `link`; моноширинный — `--color-code` / `--color-code-own`;
- разделители и рамки полей = `line` / `lineStrong`; второстепенный текст = `muted`, третьестепенный = `faint`;
- ошибки/предупреждения = `--pv-red`, «хорошо», «в сети», принятый звонок = `--pv-green`, владелец группы =
  `--pv-purple`;
- прозрачности сохранены там, где tdesktop их использует: полосы прокрутки (текст/`muted` с прежней альфой —
  чёрная альфа пропала бы на тёмном фоне), выделения (`accent` 4c/7f/33), тени пузырей (29), шапка панели эмодзи
  (`panel` f2), превью стикера (`panel` b0), подчёркивание орфографии (`red` 88);
- служебные сообщения на плоском фоне: светлый — `muted` cc с белым текстом, тёмный — `raised` e6 с текстом схемы
  (`msgServiceFg` переопределён, хотя в `colors.palette` это копия `windowFgActive`).

## Что оставлено штатным и почему (194 ключа со своим hex)

| Группа | Ключей | Почему |
|---|---|---|
| тени, затемнения, фон картинок | 19 | прозрачный чёрный работает на любой схеме |
| кнопки ботов | 8 | боты вне задачи |
| системное (закрыть в Windows, трей, устаревшая ОС) | 9 | цвета системы, не оформления |
| экран входа: самолёт | 3 | рисунок Telegram |
| цвета собеседников, значки настроек | 24 | в web `--color-peer-*` от схемы не зависят |
| значки типов файлов, карта, ролики, тосты | 24 | цвет несёт смысл; тосты тёмные в обеих темах |
| просмотрщик медиа | 24 | тёмный оверлей поверх всего |
| звонки (личные и групповые) | 46 | окна звонков тёмные в обеих темах |
| Premium, Stars, платежи, статистика, кошелёк | 37 | функции вне задачи |

Ключи вида `#hex | ключ` (25): 13 следуют за сопоставленным ключом (например, `callArrowFg` → `boxTextFgGood`),
9 — штатные. Три записаны явно: `dialogsOnlineBadgeFg` (иначе «в сети» стал бы акцентом, а не зелёным),
`emojiPanHeaderBg` и `spellUnderline` (иначе потерялась бы прозрачность).

## Как применять в tdesktop (рекомендация для T053, код не менялся)

Как штатно: встроенные темы — zip-файлы `Resources/*.tdesktop-theme` в `Resources/qrc/telegram/telegram.qrc`
(алиас `:/gui/<имя>`), описаны в `window_themes_embedded.cpp EmbeddedThemes()` (тип, цвета превью, путь).
`Window::Theme::Apply(path)` → `PreviewFromFile` → `LoadTheme` (zip: `colors.tdesktop-theme` или
`colors.tdesktop-palette` + `background.*`; не zip — текст палитры) → `KeepApplied()` пишет тему в слот текущего
режима (`Local::writeTheme`: `_themeKeyDay` / `_themeKeyNight`). Переключение день/ночь и «как в системе»
(`core/application.cpp` → `ToggleNightMode()`) берёт тему, сохранённую для другого режима
(`Local::readThemeAfterSwitch`), либо `night.tdesktop-theme`, если её нет. Путь `:/gui/…` считается встроенным
(`IsEmbeddedTheme`): файл не отслеживается и не редактируется; `ColorizerForTheme` для пути, которого нет в
`EmbeddedThemes()`, возвращает пустой колоризатор — акцент tdesktop не перекрашивает нашу палитру.

Рекомендуемый путь — **встроить 8 файлов `.tdesktop-theme`** (а не применять `.tdesktop-palette`):

1. положить `space-*.tdesktop-theme` в `Resources/`, добавить в `telegram.qrc` (`:/gui/space-<схема>-<режим>.tdesktop-theme`);
2. выбор схемы (T057) применяет файл текущего режима через `Apply(path)` + `KeepApplied()`; переход в другой
   режим (кнопка ночного режима и «как в системе») — `ToggleNightMode(путь пары)` с явным путём для выбранной
   схемы, чтобы в слот другого режима не попала прежняя тема; схема `telegram` — штатные `ApplyDefaultWithPath("")`
   / `night.tdesktop-theme`;
3. в `EmbeddedThemes()` добавлять не обязательно: там список для штатного выбора тем; если добавить — пункты
   появятся в «Настройки чатов → Тема» и попадут под колоризатор акцента (тогда задать `accentColor` пустым или
   исключить).

Почему zip, а не голая палитра: фон чата — не ключ палитры, это обои. Голая `.tdesktop-palette` оставит прежние
обои (зелёный узор). В архиве `background.png` 1×1 цвета `bg` (так же устроен штатный `night.tdesktop-theme`) даёт
плоский фон без узора; ключи «(adjusted)» (`msgServiceBg`, `historyScroll*`) при собственном фоне темы tdesktop не
подстраивает. Плоский фон и острова — T054/T058.

Сторож совпадения с web в C++-тестах ядра (T051) может читать `space-tokens.json` напрямую.
