# Parvane ↔ Telegram Desktop — паритет функций и внешнего вида

> **Статус 2026-08-10:** основной клиент теперь Web (`web/telegram-tt`, см.
> `WEB-ROADMAP.md` — этапы A/B закрыты, паритет-функционал реализован там).
> Desktop сохраняет совместимость по wire-контракту (общие форматы: E2E-inner
> JSON, PVPK1 стикер-паки, pack_ref, blobcrypt). При изменении протокола
> проверять оба клиента; кросс-клиентский e2e — `scripts/run_web_cross_client_e2e.sh`.

Цель: полная копия клиента Telegram Desktop (внешний вид 1:1 + все функции), кроме
ботов и мини-приложений. Этот документ — рабочая карта: как устроен оригинал (по
исходникам tdesktop, которые у нас уже в `desktop/tdesktop/`), что уже нативно, что
мы подменяем своими виджетами, чего нет, и план доведения.

## ГЛАВНЫЙ ПРИНЦИП (почему это выполнимо)

Наш клиент — **форк Telegram Desktop**. Весь нативный UI Telegram уже в репозитории.
Мы НЕ рисуем интерфейс сами — мы синтезируем TL-объекты (`MTPMessage`, `MTPUser`,
`MTPChat`, `MTPDocument`…) и скармливаем их штатному UI через `Data::Session`
(`addNewMessage`, `processUser`, `processChat`). Поэтому чаты, сообщения, медиа,
список диалогов, профили, настройки **уже выглядят как Telegram 1:1** — это родной
код tdesktop.

Отсюда правило паритета: **любую функцию делаем через НАТИВНЫЙ модуль tdesktop,
кормя его нашими данными из NATS. Свои QWidget/QPainter — только когда нативного
пути реально нет.** Каждый самодельный виджет = отклонение от «1:1» и его надо
устранять.

Проверка (греп по `parvane/*.cpp`): единственный файл с кастомными виджетами —
`parvane_video_window.cpp` (окно звонка). Всё остальное — нативное. Значит главный
визуальный разрыв — ЗВОНКИ.

## Карта модулей tdesktop (SourceFiles/)

- `history/` — лента сообщений (HistoryView::ListWidget/Message), композер, медиа,
  реакции, ответы, пересылки, закрепы. Мы уже кормим это через `addNewMessage`.
- `dialogs/` — список чатов слева (папки, поиск, счётчики, свайпы).
- `data/` (76 файлов) — модель: `Data::Session`, `HistoryItem`, `DocumentData`,
  `PhotoData`, `PeerData`/`UserData`/`ChatData`/`ChannelData`. Наш мост живёт тут.
- `calls/` — НАТИВНЫЙ UI звонков: `Calls::Panel` (окно), `Calls::Instance`
  (менеджер), `Calls::Call` (звонок, `final`, завязан на MTProto/tgcalls),
  `calls_userpic`, `calls_video_bubble`, `calls_video_incoming`,
  `calls_signal_bars`, `calls_emoji_fingerprint`, `calls_top_bar`, `calls.style`.
- `settings/` — экран настроек (14 разделов: аккаунт, приватность, уведомления,
  чаты, папки, продвинутое…).
- `info/` — профиль пользователя/чата, общие медиа, участники.
- `boxes/` (61 файл) — все диалоги-«боксы» (создать группу, выбрать контакты,
  отправить файл, стикеры и т.д.).
- `chat_helpers/` — панель эмодзи/стикеров/GIF, поле ввода с форматированием.
- `media/` — плеер аудио/видео, просмотрщик, запись голосовых (waveform).
- `window/` — главное окно, секции, топ-бар, темы.
- `ui/` — базовые виджеты и стили (rp-widgets, кнопки, лейблы).
- `overview/`, `profile/`, `export/`, `passport/`, `payments/`, `poll/`,
  `statistics/`, `iv/` (instant view), `platform/` (интеграция с ОС).

## Инвентаризация: функция → нативный модуль → наше состояние

Легенда: 🟢 нативно (выглядит 1:1) · 🟡 частично/кастом (надо на нативное) ·
🔴 нет.

### Сообщения 1-на-1
- Текст, доставка/прочтение, typing, online — 🟢 (кормим нативный history).
- Медиа: фото/видео/файлы/голос/видеосообщения — 🟢 рендер; голос waveform — 🟡
  (считаем `audioCountWaveform`, но надо убедиться в 1:1 виде и превью видео).
- Реакции, закреп, ответы, редактирование, удаление, пересылка — 🟢.
- Форматирование текста (жирный/курсив/моно/спойлер/ссылки/цитаты) — 🔴 (нативный
  композер умеет; надо прокинуть entities в наш `MessageContent`).
- Превью ссылок (webpage) — 🔴 (нужен `MTPWebPage` + сервис превью).
- Черновики, «Избранное» (Saved Messages), переслать в любой чат — 🔴/🟡.

### Группы и каналы
- Группы/каналы, роли, права постинга, медиа/реакции/пин — 🟢 (синтез MTPChat).
- Админка (бан/мьют/права), инвайт-ссылки, @упоминания, треды/обсуждения,
  счётчики прочтений, «прочитали N» — 🔴.

### Звонки — ГЛАВНЫЙ РАЗРЫВ
- Аудио/видео/групповые, WebRTC, MITM-защита (Ed25519+SAS) — 🟢 функционально.
- UI — 🔴/🟡: сейчас САМОДЕЛЬНОЕ окно `parvane_video_window` (не похоже на
  Telegram), рингтон есть. Надо: экран звонка на нативных стилях `calls.style` и
  виджетах (`calls_userpic`, `calls_video_bubble`, `calls_video_incoming`,
  `calls_signal_bars`, SAS через `calls_emoji_fingerprint`), топ-бар активного
  звонка (`calls_top_bar`). `Calls::Call` переиспользовать нельзя (final+MTP) —
  строим Parvane-панель из тех же стилей/виджетов, driven нашим CallManager.

### Развлекательный слой
- Стикеры — 🟢 базово (локальные паки `~/.local/share/ParvaneStickers/<Пак>/
  *.webp|png` или `PARVANE_STICKERS_DIR` → синтез установленных наборов
  (feedSetFull) → нативная панель chat_helpers; отправка из панели →
  перехват `SendExistingDocument` → E2E-блоб в cloud (kind=sticker); приём —
  `documentAttributeSticker`, рендер нативный; Recent работает; e2e —
  `verify_stickers.sh`). ВАЖНО: загрузка паков отложена (t+3с) — init-чейн
  storage стирает наборы, если грузить раньше. Пробелы: анимированные
  tgs/webm, кастом-эмодзи, обмен паками между пользователями (сейчас паки
  локальные у каждого).
- GIF — 🟢 (attach .gif → kind=gif → нативный автоплей-пузырь «GIF» у обеих
  сторон; вкладка GIFs (Saved GIFs) наполняется отправленными/полученными
  гифками, восстанавливается реплеем журнала; отправка из вкладки — нативный
  SendExistingDocument → E2E). ВАЖНО: имя файла обязано иметь видео-расширение
  (enforceNameType(Video) иначе деградирует в файл); нативный персист Saved
  GIFs ОТКЛЮЧЁН (storage_account) — синтетические доки не переживают
  round-trip и битое чтение обрывало init-чейн (пропадала вся история).
- Анимированные стикеры — 🟢 (tgs=lottie и webm в локальных паках: панель
  рендерит анимацию, отправка/приём через E2E как статичные).
- Кастом-эмодзи — 🔴.
- Опросы (poll) — 🟢 (нативный `history_view_poll` + `CreatePollBox`; опрос
  едет в E2E-контенте kind=poll, голоса — kind=poll_vote (сервер не видит),
  агрегация на клиенте (applyResults через updateMessagePoll), закрытие,
  quiz/multi/анонимность, persist через журнал; e2e — `verify_polls.sh`).
  Пробелы: «кто голосовал» (public voters список), close_date/period-таймер.
- Геолокация/live-локация, контакты-вложения — 🔴.

### Приватность/безопасность
- TLS транспорта — 🟢. Защита звонков — 🟢.
- E2E-шифрование текста/медиа/групп (Olm+Megolm, sealed sender, ротация ключей,
  safety numbers) — 🟢 (лучше «секретных чатов»: E2E по умолчанию везде).
- Самоуничтожение/TTL — 🟢 текст И медиа/стикеры/гифки (нативный ttl_period,
  TTL внутри E2E-content; эфемерное не журналируется).
- Локальный персист истории (переживает рестарт/релогин) — 🟢.

### Приложение
- Настройки, профили, общие медиа, поиск — 🟢 нативно (частично не подключены к
  нашим данным — проверить каждую вкладку).
- Папки, архив, закреплённые чаты — 🟡/🔴.
- Уведомления (нативные) — 🟡 (проверить, что триггерятся на наши сообщения).
- Темы оформления — 🟢 нативно (рескин Фазы 5 — по желанию).

### Явно НЕ делаем (просьба пользователя)
- Боты и Bot API, мини-приложения Telegram. Также вне ядра: Stories, Premium,
  платежи.
- Stories (решение 2026-07-19, веб-клиент): в telegram-tt НЕТ UI создания
  историй (веб-Telegram умеет только просмотр + реакции, единственный метод —
  sendStoryReaction). Просмотр без постинга — мёртвая функция; отложено до
  появления постинга в апстриме tt либо явного запроса на свой UI.

### Мультидевайс (ЯДРО СДЕЛАНО 2026-08-14, веб-клиент; коммит 6d4626dd)
- РАБОТАЕТ (Web↔Web): per-device прекеи в identity, fan-out sealed-копий на
  все устройства получателя и свои устройства (message_device_copies +
  подмена в sync по device_id), SKDM-fan-out в группах. Второй логин НЕ
  перетирает identity первого устройства; новые входящие и исходящие видны
  на обоих. Старая история на новом устройстве — через экспорт/импорт ключей
  (E2E честный). e2e: scripts/run_web_multidevice_e2e.sh.
- DESKTOP-ДОЛГ: parvane_client.cpp шлёт ОДНУ копию (устройство '') — desktop
  читает всё, как раньше (wire back-compat, cross_client зелёный), но
  сообщения С desktop читает только одно устройство получателя. Нужен
  fan-out по бандлам из prekeys.fetch (поле devices).
- Settings→Devices СДЕЛАНО 2026-08-17 (Web): identity.device.list/revoke во
  всех слоях контракта, нативный экран Active Sessions кормится нашими
  устройствами, отзыв ротирует Megolm (своих групп и общих групп у контактов
  отозванного). e2e: scripts/run_web_devices_e2e.sh. DESKTOP-ДОЛГ: экран
  Sessions в tdesktop не подключён к identity.device.* (показывает пусто).
- Авто-линковка истории СДЕЛАНА 2026-08-17 (Web↔Web): identity.link.* +
  extra_signing в msg.sync.request (опциональное поле — desktop-совместимо).
  e2e: scripts/run_web_linking_e2e.sh. DESKTOP-ДОЛГ: desktop не публикует
  офферы и не выдаёт гранты — линковка работает только между web-установками;
  desktop-историю на web по-прежнему переносить ручным экспортом ключей.

### Регистрация через почту (СДЕЛАНО 2026-08-14, веб-клиент)
- За флагом `PARVANE_EMAIL_REQUIRED=1` на identity: register + email → код из
  письма → identity.email.confirm; без флага поведение прежнее. Детали — в
  корневом CLAUDE.md. e2e: scripts/run_web_email_e2e.sh.
- DESKTOP-ДОЛГ: intro_parvane не знает про email/код — при включённом флаге
  desktop может логиниться в подтверждённые аккаунты, но НЕ регистрировать
  новые (register вернёт «нужен корректный email»). Нужны поля email+код в
  intro_parvane.cpp, когда дойдём до desktop-обвязки.

## План реализации (приоритеты)

СДЕЛАНО из прежнего плана (июль 2026): нативный экран звонка, форматирование,
превью ссылок, черновики, уведомления, стикеры (локальные паки) + GIF-приём,
опросы, админка групп, @упоминания, E2E по умолчанию (сильнее «секретных
чатов»), TTL текста, папки.

**ФОКУС: ТОЛЬКО МЕССЕНДЖЕР** (решение пользователя, июль 2026). Рескин UI и
Календарь/Дневник отложены до явного указания. Оставшиеся пробелы:

1. **P1 — Развлекательный слой** — 🟢 СДЕЛАНО, кроме кастом-эмодзи.

   **ОТЛОЖЕНО (бэклог, вернуться после P2): КАСТОМ-ЭМОДЗИ.** Объём — как
   стикеры целиком: (а) entity custom_emoji в E2E-контенте (document_id);
   (б) инлайн-рендер: Data::CustomEmojiManager резолвит документы через
   MTProto — отвязать на наши локальные документы (setLocation, как стикеры);
   (в) секция кастом-эмодзи в Emoji-панели (feedSetFull с флагом Emoji,
   documentAttributeCustomEmoji); (г) обмен паками — переиспользовать
   pack_ref-механизм стикеров.
2. **P1 — Опросы, доводка** — 🟢 СДЕЛАНО: аватарки голосовавших (public),
   свой бокс «кто голосовал» (перехват showPollResults), пересылка (копией,
   нативная метка Forwarded). Таймер close_period НЕ делаем — его нет и в
   оригинальном Telegram Desktop.
3. **P1 — TTL для медиа** — 🟢 СДЕЛАНО (ttl_secs в контенте медиа/стикеров,
   ttl_period на приёме, эфемерное не журналируется).
4. **P2 — Группы-крупняк**: гранулярные права админов, бан/мьют,
   инвайт-ссылки, треды/обсуждения, счётчики прочтений.
5. **P2 — Геолокация/live-локация, контакты-вложения.**
6. **P3 — Мультидевайс-синк** — ЯДРО СДЕЛАНО 2026-08-14 для Web (см. секцию
   «Мультидевайс» выше); остался desktop-fan-out + Devices UI + линковка.
7. **P3 — Голосовые чаты/трансляции; запланированные/тихие сообщения.**
8. **P3 — Аудит вкладок настроек/профиля на наши данные; архив чатов.**

ОТЛОЖЕНО (не мессенджер): рескин (быв. Фаза 5), Календарь/Дневник (быв. Фаза 6).

Правило на каждый пункт: сперва найти нативный модуль, потом прокинуть в него наши
данные из NATS; свои виджеты — только если нативного пути нет.
