# Parvane desktop — security review (2026-08-22)

Аудит нового desktop-кода (перенос web-функционала: E2E/мультидевайс/линковка/
email + геолокация/typing/scheduled/кастом-эмодзи). Проводился отдельным
агентом по всему диффу сессии.

## Исправлено
- **CRIT — групповая подмена отправителя.** Верификация отправителя была
  только под `direct` (1-на-1); для `group_encrypted` `sm.from` брался из
  контролируемого отправителем Megolm-плейнтекста (`inner.from`) → любой
  участник группы выдавал себя за другого. Фикс: для групп автор — ВСЕГДА
  gateway-аутентифицированный wire `from` (подделать нельзя), `inner.from` не
  доверяется; verifySender теперь запускается и для групп; sender_identity
  кэшируется для обоих путей (иначе cached-путь групп доверял бы подмене).
  (parvane_client.cpp, prepareIncoming.)
- **MED — материализация кастом-эмодзи паков.** (а) лимит 4 пака/сообщение
  (анти-DoS фан-аут скачиваний); (б) НЕ перезаписываем существующий пак (guard
  `QDir(dest).exists()`) — иначе отправитель, зная имя, подменил бы содержимое
  и docId (детерминированный от имени|файла). Путь-траверсал и size-бомбы уже
  закрыты (SanitizePackName + basename-санитизация + kPackMaxBytes/Files).
- **LOW — scheduled.** Клампим задержку таймера (анти-переполнение при
  испорченном далёком `due` на диске).
- **LOW — linking.** Guard на отказ RAND_bytes (не шифруем с пустым IV).

## Проверено ОК
- Крипто линковки (ECDH P-256/HKDF/AES-GCM): свежий 12-байтовый IV на seal,
  проверка тега на open, salt/info совпадают с web. FFI Rust — memory-safe.
- Само-копии/sender_signing_key на проводе — деанонимизация против сервера
  (LOW, наследуется от web, структурно необходимо для sealed sender).
- Линковка против ВОРА ПАРОЛЯ — защищена (SAS-код + ConfirmBox на старом
  устройстве; грант одноразовый, TTL, привязан к живому офферу).
- Async/concurrency в новых путях — корректные снапшоты под g_sessionMutex,
  weak-guards в api_authorizations.

## Известные ограничения (паритет с web, не desktop-регрессии)
- **Грант линковки не аутентифицирован к подтвердившему устройству**
  (MED, паритет с web): злонамеренный СЕРВЕР мог бы подделать грант (свой
  эфемерный ключ + бокс, который расшифруется) и подсунуть новому устройству
  контролируемый decCache/контакты. Порог — полностью злонамеренный сервер
  (E2E-противник). Настоящая защита — подпись гранта ключом аккаунта +
  привязка SAS к гранту — протокольная доработка (затрагивает и web).
- **Групповой typing — послабление gateway** (LOW, принятый компромисс):
  `allowed_sub` пускает подписку на любой конкретный `msg.typing.<id>` — юзер,
  знающий адрес, может видеть факт набора «кому-то». Только эфемерная
  метадата, без содержимого; `from` не подделывается (штампует gateway);
  wildcards по-прежнему запрещены. Плотная защита требует состояния членства
  в gateway.
